MCP Server Cards (ext-server-card, SEP-2127)

AAIFspecificationcore entry

Verified 2026-11-02. Status as of 2026-10-13. All entries.

Seams: S1

Status

Experimental extension of MCP: the README of the extension repository still reads "not an accepted or official MCP extension" (2026-10-13). SEP-2127 (PR #2127, "MCP Server Cards - HTTP Server Discovery", Extensions Track) was merged on 2026-10-06 (14:43 UTC, merge commit 0a11bf6) by a maintainer of the MCP repository; the Specification Enhancement Proposal (SEP) file, read 2026-10-13, carries "Status: Final" and says the full extension specification stays in the extension repository, graduating to a repository named ext-server-card on acceptance. The last commit of the extension repository on main is of 2026-08-12 (PR #47); latest activity read: issue #30 (2026-10-10, 9 comments).

Relevance

A Server Card is "a static metadata document that describes a remote MCP server enough for clients to discover and connect to it"; cards "intentionally omit primitive listings (tools, resources, prompts)". docs/discovery.md says clients performing domain-level discovery SHOULD attempt to retrieve /.well-known/ai-catalog.json, whose entries of type application/mcp-server-card+json point to the cards.

Commerce metadata was kept out of the card: in issue #27 (closed 2026-06-13) a member of the modelcontextprotocol organisation (GitHub author association MEMBER, read 2026-10-13) answered "we do not intend to introduce MCP-specific patterns (like _meta) into the MCP Catalog"; SEP-2007 (payment support) was closed 2026-06-24 as "dormant". The individual draft draft-morrison-mcp-dns-discovery-09 (Informational, dated 21 October 2026, posted 2026-10-22; text read 2026-11-02) defines DNS discovery for remote MCP servers: a TXT record at _mcp.<domain> gives the endpoint URL and transport and optionally an Ed25519 key, which a client checks against the server's TLS certificate, its RFC 9421 response signatures or the key declared in its Server Card (section 5.3.6); "If verification fails, the client MUST treat the server as untrusted". It also defines two other TXT records, _org-alter.<domain> and _alter.<domain>. It is not adopted by a WG and is not counted among the discovery paths on the home page; its author proposed this addition in issue #22 of this map's repository and states being a co-founder of ~alter, which publishes an _mcp record for its own domain.

Boundary

The README says a Server Card "describes remote connectivity only"; local installation metadata stays in the MCP Registry server.json.
