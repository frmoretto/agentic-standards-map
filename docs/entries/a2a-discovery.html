A2A protocol, agent discovery

AAIFwork-itemcore entry

Verified 2026-10-23. Status as of 2026-10-23. All entries.

Seams: S1

Status

A2A registers /.well-known/agent-card.json for a single AgentCard. PR #2240 was merged on 2026-10-21 (23:12 UTC, merge commit 8faec73) into the branch dev-1.1, not into main: at that commit docs/topics/agent-discovery.md calls the well-known URI "A simple option for single-agent deployments." with the limit "One Agent Card per domain.", and heads the next mechanism "AI Catalog Discovery (/.well-known/ai-catalog.json)", marked "Preferred" and "the recommended approach for public agents". On main the file does not mention ai-catalog (2026-10-23). Issues #2276 (4 comments, the last of 2026-10-20) and #2248 (no comment), which propose other paths for hosts serving several agents, were open on 2026-10-23.

Relevance

PR #2240, merged into the branch dev-1.1 on 2026-10-21, makes /.well-known/ai-catalog.json the "Preferred" discovery mechanism, and issue #2276 proposes /.well-known/agent-card-list.json for providers serving multiple agents. The documentation (docs/topics/agent-discovery.md on main) says "The current A2A specification does not prescribe a standard API for curated registries."; AI Catalog and Agentic Resource Discovery (ARD) not found in that file (2026-10-03); ai-catalog not found in it on 2026-10-23. darrelmiller wrote on issue #1807 (2026-05-12) "Rather than layering trust information into the AgentCard, we are attempting to use AI Catalog to contain that kind of trust information." HTTP Archive custom-metrics PR #176, merged on 2026-10-07, adds a metric for "/.well-known/agent-card.json" to track its presence and key metadata.

Committed next

None declared in the sources read.

Boundary

A maintainer wrote on PR #418 that the A2A working group "will not be building any kind of registry standard".

Author participation

The author of this map took part in issue #2276 (two comments, 2026-10-02); see Disclosure.
