Shopify, MCP surfaces for buyer agents, developers and merchants

Industrywork-itemcontext entry

Verified 2026-11-09. Status as of 2026-11-09. All entries.

Seams: S1S4

Status

Three distinct MCP surfaces are documented or published by Shopify: checkout for buyers' agents (server-side Checkout MCP and, since 2026-09-28, Checkout WebMCP), the local developer package @shopify/dev-mcp (latest version 1.16.0, 2026-09-25), and a remote MCP for merchants at setup.shopify.com/mcp. For the merchant surface the source is Shopify's own toolkit repository; no page on shopify.dev was found for it. A fourth surface is for shoppers' agents: the command-line client @shopify/shop (npm, MIT; version 1.0.3 published 2026-10-08, 01:20 UTC, after 1.0.2 on 2026-10-07), whose repository Shopify/shop has its latest commit d1e8c7c on main (2026-10-08, 01:17 UTC); neither the README, the skill file nor the transactions reference declares a beta or preview status or a list of supported countries (not found, 2026-10-13). Read 2026-11-09: the latest toolkit release is v2.3.0 (2026-10-27, Shopify Flow workflows through the Admin API), after v2.1.2 (2026-10-14) and v2.2.0 (2026-10-16, whose notes say the OpenAI plugin packages "an exact Shopify MCP configuration, and content-free UCP telemetry"); at the tag v2.3.0 the folder skills/ucp still holds SKILL.md and .cursor-plugin/mcp.json still declares the remote MCP at setup.shopify.com/mcp.

Relevance

Buyers' agents: the documentation says "Use Checkout WebMCP when your agent runs in the buyer's browser. If your agent can run on a server, then use Checkout MCP", and that Checkout WebMCP "implements the UCP checkout capability (dev.ucp.shopping.checkout)"; see ucp and browsers-webmcp. Developers: @shopify/dev-mcp is a local npm package (npm registry, read 2026-10-08 and 2026-10-13, version 1.16.0 published 2026-09-25).

Merchants: Shopify-AI-Toolkit v2.1.0 (2026-10-01) states "The Cursor plugin, which Grok Bot also installs from the Cursor Marketplace, now connects to Shopify's remote MCP at setup.shopify.com/mcp"; the file .cursor-plugin/mcp.json at that tag declares an http server with that URL and an auth block with a client id, and v2.1.1 (2026-10-08) changes the plugin description to "Create and manage your store with Shopify". The toolkit release v2.0.1 says "Regenerated agent skills from @shopify/shopify-dev-tools 1.17.1"; the package @shopify/shopify-dev-tools returns E404 on the npm registry (2026-10-08 and 2026-10-13).

Since v2.0.0 the toolkit publishes UCP as a separate skill: the CHANGELOG entry for 2.0.0 reads "UCP ships separately as ucp", and the folder skills/ucp at the tag v2.1.1 (commit 26d0623, 2026-10-08, 00:34 UTC) holds a SKILL.md named ucp whose description begins "Use when the user wants to use the UCP CLI to find, compare, buy, or track products from online merchants" and which requires the binary ucp (read 2026-10-13).

Shopper's agents: the README of Shopify/shop (commit d1e8c7c, read 2026-10-13) says the command-line interface (CLI) "lets agents search millions of stores, build carts, check out and pay with the shopper's Shop account, and track orders" and is a client of Shop's MCP server at mcp.shop.com. It says: "Some stores have no agent checkout API (UCP); the agent has to enter a payment credential into the site's checkout form in a browser." For that case the shopper approves a "spend request" on Shop and the agent receives a one-time credential up to the approved limit; the skill file says "Prefer Shop/UCP checkout when available". The reference skills/shop/references/transactions.md says of the agent's report on the purchase "This records your report, not payment confirmation.", of a credential state "consumed without an instrument does not establish credential delivery or payment.", and of cancelling the request "this does not cancel/refund the purchase or revoke an issued credential." The core of the CLI is a compiled binary (lib/shop.wasm, about 1.9 MB), so its logic is not readable as source; the repository holds nine commits, all of 2026-10-07 and 2026-10-08.

No call was made to any MCP or OAuth endpoint; only documentation, repositories and listings were read.
